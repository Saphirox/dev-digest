# Review pipeline — специфікація движка

**Модуль:** `@devdigest/reviewer-core` · без БД, GitHub і файлової системи

Що саме відбувається між «є diff» і «є знахідки», і які інваріанти тут не
можна порушувати.

## Конвеєр

```
diff ──► assemblePrompt ──► LLMProvider ──► parseWithRepair ──► groundFindings ──► Review
         (prompt.ts)        (llm/*)         (output/*)          (grounding.ts)
```

Єдиний побічний ефект усього пакета — виклик LLM через **інжектований**
`LLMProvider`. Саме тому движок тестується без ключів і без мережі: тест
підсовує заглушку.

## Інваріанти

**1. Заземлення обов'язкове.** Кожна знахідка мусить посилатися на реальний
рядок diff (`groundFindings`), інакше її **відкидають**. Модель не може
«вигадати» файл чи рядок і протягнути це в результат.

**2. Оцінка перераховується.** `score` рахується із **тих знахідок, що
вижили** після заземлення. Значення `score`, яке повернула модель, не береться
на віру ніколи.

**3. Захист від ін'єкцій — одне спільне правило, а не пошук ключових слів.**
`INJECTION_GUARD` (`prompt.ts`) повідомляє моделі, що вміст PR — це **дані, а
не інструкції**, а `wrapUntrusted` позначає межі ненадійного тексту. Заяви на
кшталт «це навмисно / це тест / не позначай це» **не знижують severity**.
Денилист поруч додавати не треба — він обходиться тривіально.

**4. Структурований вихід із ремонтом.** `structured.ts` будує JSON Schema з
Zod; `parseWithRepair` дає моделі шанс виправити невалідний JSON, перш ніж
падати.

## Вартість

`run.ts` підсумовує `usage.cost` по всіх чанках map-reduce і повертає
`ReviewOutcome.costUsd`. Ланцюжок джерел: `usage.cost` від OpenRouter → живий
прайс-бук → статична таблиця → `null`.

**Акумуляція all-or-nothing:** якщо хоч один чанк не повернув вартості,
підсумок не вигадується — краще `null` («невідомо»), ніж занижена цифра. Далі
сервер зберігає це число як є (див.
[`../../server/specs/run-cost.md`](../../server/specs/run-cost.md)).

## Порожні слоти промпта — не мертвий код

`assemblePrompt` приймає необов'язкові слоти пізніших уроків (`skills`,
`memory`, `specs`, `callers`). У стартері сервер їх не передає, і секції просто
не потрапляють у промпт. **Видаляти їх не можна.**

## Межа пакета

Ніякого доступу до БД, файлової системи чи GitHub. Якщо фічі це потрібно — вона
належить `server`, який передає сюди готовий результат звичайним аргументом.
Порушення цієї межі — головна причина, чому движок перестане бути тестованим.
