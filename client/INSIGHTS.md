## Codebase Patterns

- 2026-09-17 · Run-usage UI: null and 0 mean different things for BOTH cost and tokens. Unknown cost renders "—" (`client/src/lib/format-usd.ts`, `formatUsd`); unknown tokens must DROP the whole "N tok · " segment. Never `?? 0` into `RunCostBadge` — `(r.tokens_in ?? 0) + (r.tokens_out ?? 0)` made a run with known cost but unrecorded tokens claim "0 tok". Guarded by "does not claim '0 tok'" in `RunHistory.test.tsx`. → now a rule in client/AGENTS.md.
- 2026-09-17 · Reuse `client/src/vendor/ui`'s **tokens** before its components: `SEV[x].c` / `SEV[x].icon` (`client/src/vendor/ui/primitives/tokens.ts:6`) give the right colour and glyph for any severity UI, while the matching components bake in chrome. `SeverityBadge` (`client/src/vendor/ui/primitives/Badge.tsx:52`) unconditionally draws a filled pill (`background: SEV[x].bg` + padding + radius + uppercase) with no variant prop — the timeline chips needed a bare icon+number, so the chip had to be local.
- 2026-09-17 · `FindingsTab`'s two run props are different types and trivially swapped: `runs` is `ReviewRecord[]` (each WITH `findings` and a `run_id`), `prRuns` is `RunSummary[]` (the timeline). Anything per-severity must read `runs` and join by `run_id` — `RunSummary` carries only `findings_count`/`blockers`, never a severity breakdown (`client/src/vendor/shared/contracts/trace.ts:99-121`). `client/src/app/repos/[repoId]/pulls/[number]/_components/FindingsTab/FindingsTab.tsx:17-18`.
- 2026-09-17 · The seeded review has `run_id = NULL` (`server/src/db/seed.ts:136-148` never sets it) and every real `agent_runs` row in the shared dev DB has 0 findings — so anything joining reviews to timeline runs by `run_id` renders its fallback and looks broken on seeded data. To see the timeline severity chips, temporarily `UPDATE findings SET review_id=<a review that HAS a run_id>` and put it back; don't "fix" the seed (`e2e/INSIGHTS.md` explains why).
- 2026-09-18 · When a count and the list it describes can diverge, derive them in the SAME component. The run card's severity pills must equal the finding cards below, but `FindingsPanel` owns the "hide low confidence" toggle — counting `review.findings` up in `ReviewRunAccordion` would promise cards the toggle had hidden. Counting inside the panel, post-confidence and pre-severity, makes the equality structural. `client/src/app/repos/[repoId]/pulls/[number]/_components/FindingsPanel/FindingsPanel.tsx:33`.
- 2026-09-18 · `@devdigest/ui` exports its own `Severity` with a fourth value (`INFO`) the contract's `Severity` lacks, so importing both in one file is a duplicate-identifier error and `Record<ContractSeverity, number>` won't satisfy a `Record<UiSeverity, number>` param. Type props from the CONTRACT and alias the UI one (`type Severity as UiSeverity`) at the `SeverityBadge` call. `client/src/vendor/ui/primitives/tokens.ts:3` vs `client/src/vendor/shared/contracts/findings.ts:11`.
- 2026-09-19 · The Trace drawer shows findings from TWO independent sources, so the numbers can legitimately disagree: the `FINDINGS` stat tile reads `stats.findings` off the run's `RunTrace` document; the `Findings` section below renders the separately-passed `findings: FindingRecord[]` (persisted rows). `FINDINGS 0` above a list of 3 is not a bug — don't "reconcile" without deciding which source is authoritative. `client/src/app/repos/[repoId]/pulls/[number]/_components/RunTraceDrawer/_components/TraceBody/TraceBody.tsx:19` (`TraceBody`).
- 2026-09-19 · PR-list columns derive from one `COLUMNS` array (`client/src/app/repos/[repoId]/pulls/constants.ts:1`): `GRID`, the header row and the cell order all come from it, and `PRRow` builds `cells: Record<ColumnKey, ReactNode>`, so a column added without its cell is a `tsc` error (TS2741). The one link the type system can't see is the header label `list.columns.<key>` in `prReview.json` — guarded by `client/src/app/repos/[repoId]/pulls/constants.test.ts`. (Replaces the old three-unlinked-places trap: `GRID` + `COLUMN_KEYS` + JSX cells.)
- 2026-09-19 · UI state that must survive moving between `/x` and `/x/:id` (e.g. the agents rail's "sorted once per page load" order) has to live in a Next `layout.tsx`, not a component each page renders — separate pages remount it on every navigation. `client/src/app/agents/layout.tsx:1` mounts `AgentsLayout` once; pages render only the right pane, and the create-modal trigger reaches them via `AgentsShellContext`.

- 2026-09-20 · `MonoLink` (`client/src/vendor/ui/primitives/MonoLink.tsx:25`) renders an `<a>` ONLY when `href` is set and otherwise falls through to a `<button className="mono">` — so a call site that passes `href={undefined}` to mean "no link" ships a focusable, `cursor:pointer` control with no handler, and an RTL `queryByRole('link')` absence check passes VACUOUSLY (a `<button>` can never match it). Seen in `RiskRow`/`RiskAreas.test.tsx`: the test named "renders as plain text with no link role" certified the opposite of the truth; the honest assertion is `queryByRole('button', { name: <ref text> })`, which FAILS today. Third member of the same family after `Badge` silently dropping `aria-label` and `ConfidenceNum` hardcoding `title`: **a vendored primitive does something other than its prop name implies — assert the absence of the role it actually renders, not the one you intended.**
- 2026-09-21 · Smart Diff findings are one `<button>` per PRESENT severity (`FindingSeverityDots`, worst-first by `SEVERITIES`), each with a VISIBLE count and an accessible name like "1 Critical finding"; a click jumps to the first finding of that severity. Assert with `getAllByRole("button", { name: /finding/ })` + `toHaveAccessibleName` — `toHaveTextContent` misses a name that lives only in `aria-label`. `FileCard` keeps only the `pathAdornment` slot. `client/src/app/repos/[repoId]/pulls/[number]/_components/SmartDiffViewer/_components/FindingSeverityDots/FindingSeverityDots.tsx:18`
- 2026-09-22 · `client/src/components/diff-viewer/FileCard/FileCard.tsx`'s test lives ONE LEVEL UP, at `client/src/components/diff-viewer/FileCard.test.tsx` (sibling of the `FileCard/` folder, not inside it) — same for `CodeLine/CodeLine.tsx` vs `CodeLine.test.tsx`. Deviates from the documented "colocated `<Name>.test.tsx` beside the component" convention. Extend the existing outer file rather than creating a second, shadowed one inside the folder.
- 2026-09-22 · `DiffTab.tsx` imports `usePrComments`/`useCreatePrComment` from `@/lib/hooks/reviews` and `usePrSmartDiff` from `@/lib/hooks/smart-diff` directly, NOT the `@/lib/hooks` barrel that sibling `SmartDiffViewer.test.tsx` mocks — `vi.mock("@/lib/hooks", …)` would silently miss DiffTab's calls (module mocking is per-specifier). Mock each hook's own module path, matching the exact import in the file under test. `client/src/app/repos/[repoId]/pulls/[number]/_components/DiffTab/DiffTab.tsx:7-8`.
- 2026-09-27 · A card's own section label can sit either OUTSIDE its bordered `Card` (the `IntentCard` precedent: `<section><header/><Card>…</Card></section>`, label above the box) or INSIDE it — the two look identical in prose ("follow the Card + SectionLabel precedent") but differ in the reference screenshot. `BlastRadiusCard` needed the label (`SectionLabel icon="Workflow"`) as the FIRST child inside `<Card>`, confirmed only by zooming into `docs/images/blast-radius/02-card-tree-view-detail.png` (the card's own border wraps the "BLAST RADIUS" line). Don't infer label placement from a sibling component's code; check where the border actually starts in the screenshot. `client/src/app/repos/[repoId]/pulls/[number]/_components/BlastRadiusCard/BlastRadiusCard.tsx:82`.
- 2026-09-27 · No responsive (`@media`) grid existed anywhere in `client/src` before this (checked with `grep -rn '@media|minmax|auto-fit'`) — every existing 2-column layout (`IntentCard/styles.ts`, `ShortcutsHelp.tsx`) is a fixed `gridTemplateColumns: "1fr 1fr"` with no breakpoint, since inline `style` objects can't express `@media`. For the Overview tab's 2-col-collapsing-to-1-col requirement, the precedent to follow is `.skill-md` in `globals.css` (a small, purpose-named SCOPED global class, not new component CSS-in-JS) — added `.overview-grid` there rather than inventing a JS media-query workaround. `client/src/app/globals.css:26` (`.overview-grid`).
- 2026-09-27 · An empty-body early return placed BEFORE a status/notice component in the JSX tree silences that notice for the exact case it matters most: `BlastRadiusCard`'s `if (blast.changed_symbols.length === 0) return <...noSymbols/>` sat above `<DegradedNotice reason={blast.reason} .../>`, so an unindexed repo (`degraded: true, reason: "no_data"`, `changed_symbols: []`) rendered only the generic "No changed symbols" text — the one signal explaining *why* was never reached. Fix pattern: compute the empty/degenerate condition as a `const` (`hasChangedSymbols`), keep it out of the return path entirely, and let it choose only the body content (ternary) placed AFTER any notice/banner that must render regardless of body state. `DegradedNotice` itself already no-ops correctly (`if (!reason) return null`, `DegradedNotice.tsx:42`) — the bug was purely in the parent's control flow. `client/src/app/repos/[repoId]/pulls/[number]/_components/BlastRadiusCard/BlastRadiusCard.tsx:55-101`.
- 2026-09-27 · `var(--text)` is not a defined CSS token; only `--text-primary`, `--text-secondary` and `--text-muted` exist (`client/src/vendor/ui/styles.css:17-19`). An invalid `var()` silently falls back to the inherited colour, so neither `tsc` nor the tests catch it. It was used in `IntentCard/styles.ts:35` and `RiskAreas/styles.ts:33` (both fixed to `var(--text-primary)` in `docs/plans/0012-blast-radius-polish.md`, deltas D4/D9).
- 2026-09-29 · Agent and skill Context tabs share one cross-route `ProjectContextPicker` (`client/src/components/project-context-picker/`) that OWNS no saved state: the caller passes `value: string[]` and `onChange`, and each tab keeps an optimistic `pending` override (`pending ?? entity.context_paths ?? []`), set on change and cleared in the per-call `onSettled` of `mutate` — TanStack v5 fires per-`mutate` callbacks only for the LAST call, so rapid ticks clear `pending` once, on the final settle; a failure then falls back to the saved list (the global mutation error toast reports it). `ContextTab.tsx` in `AgentEditor/_components` and `SkillEditor/_components`.
- 2026-10-02 · Every failed mutation already raises a global error toast (`MutationCache.onError` → `notify.error`, `src/lib/providers.tsx:37`), so a spec that also wants the failure reason INLINE next to the button (PR Brief generate/refresh, spec-0002 EC-6/EC-7) shows it twice. There is no per-mutation opt-out in `MutationCache` today (no `meta` check); `PrBriefBlock` renders the inline `role="alert"` anyway. If the duplicate is unwanted, add a `meta: { silent: true }` branch there rather than catching the error in the hook. `client/src/app/repos/[repoId]/pulls/[number]/_components/PrBriefBlock/PrBriefBlock.tsx` (`generate.isError`).

## Tool & Library Notes

- 2026-09-20 · `curl`ing a page's SSR HTML to check whether a feature's text rendered is unreliable when the feature's data comes from a `"use client"` TanStack Query hook (no SSR prefetch/hydration boundary here — `src/lib/providers.tsx:22` makes a FRESH `QueryClient` per request via `useState`): the raw HTML always reflects the pre-fetch (loading) render, never the resolved data. Worse, `grep`ing for the expected copy gives a FALSE POSITIVE anyway — next-intl serialises the ENTIRE per-namespace messages JSON into the RSC flight payload (`self.__next_f.push([...])` inline scripts) regardless of whether any component actually rendered it, so a string like `"Core logic"` or `"src/config.ts"` (the latter from an unrelated `eval.json` placeholder) shows up in the curl'd HTML even when the real component never mounted. Real verification of client-fetched UI needs a JS-executing browser; a curl check only proves the page 200s and the JS bundle contains the expected symbol names (`grep` the compiled `page.js` chunk, not the HTML). Seen verifying `SmartDiffViewer` (`docs/plans/0004-smart-diff.md`).
- 2026-09-17 · There is no popover/tooltip/hovercard primitive in `client/src` (no floating-ui/radix dep) — hand-roll it. What works against the timeline's own `overflow`: `position: fixed` anchored to `e.currentTarget.getBoundingClientRect()` captured on `onMouseEnter`, clamped with `Math.min(rect.left, window.innerWidth - width)`. Keep the card a DOM child of the hovered element — `onMouseLeave` follows DOM containment, not visual position. `client/src/components/findings-preview/styles.ts:8` (`card`).
- 2026-09-17 · `ConfidenceNum` (`client/src/vendor/ui/primitives/ConfidenceNum.tsx:8`) hardcodes `title="Model confidence"` with no prop to suppress it; on a non-interactive surface such as a hover card that lone `title` makes the browser show a help cursor (user-reported; confirmed — every element computed `cursor: default` and the repo has no `cursor: help`). Need the visual without the tooltip → duplicate its ~8 lines locally (`client/src/vendor/ui` is off-limits) with a comment saying why. Corollary: name chips with `aria-label`, never `title`. Guarded in `RunHistory.test.tsx`.
- 2026-09-19 · Verifying/screenshotting the findings UI in a browser: move the pointer off the chips BEFORE clicking or scrolling elsewhere. The preview card only closes on `onMouseLeave`, so a programmatic click/`scrollIntoView` leaves it floating over the next screenshot (it also swallowed an accordion click, toggling the wrong row). Hover a far corner first, then act. `client/src/components/findings-preview/FindingsPreviewCard.tsx:1`.
- 2026-09-19 · Two `@devdigest/ui` form traps: `Button` sets no default `type`, so any `Button` inside a `<form>` (e.g. Cancel) SUBMITS it unless given `type="button"`; and `Modal` gives children no padding (`Drawer` does), so a form dropped straight in touches the edges — wrap it in a `{ padding: 24 }` div as `CreateAgentModal` does. `client/src/vendor/ui/kit/Modal.tsx:60`. → now a rule in client/AGENTS.md.
- 2026-09-19 · `@devdigest/ui`'s `Markdown` renders into a `dd-md` div with NO stylesheet anywhere, and the global reset strips heading sizes and list bullets, so every rendered markdown reads as flat paragraphs. Don't fix `.dd-md` globally (PR descriptions and findings rely on the flat look); scope document typography to the surface that needs it, as the skill preview does with `.skill-md` in `client/src/app/globals.css:1`.
- 2026-09-20 · `Badge` (`client/src/vendor/ui/primitives/Badge.tsx:9`) destructures a fixed prop list with no `...rest` spread, so `aria-label` passed to it is silently dropped — it never reaches the rendered `<span>`. Same family of trap as the `ConfidenceNum`/`title` one: to label a chip built from `Badge` (or any vendor/ui primitive without a matching prop), wrap it in `<span aria-label={...}>` with `aria-hidden="true"` on the Badge's own content, don't pass the prop straight through and assume it worked (`tsc`/tests won't catch a dropped prop either). `client/src/app/repos/[repoId]/pulls/[number]/_components/IntentCard/IntentCard.tsx:63-69`.
- 2026-09-20 · A plan's text-only design description ("highlighted INTENT chip") turned out, once the user shared the actual reference screenshot, to mean plain colored text + a small icon with NO background — the "highlight" was a human's yellow highlighter-pen annotation drawn over the crop to point at the element, not a literal colored-background component. Don't commit to a colored-`Badge`-with-background reading of a text-only crop description before a real screenshot is available; treat it as the open question it is. `client/src/app/repos/[repoId]/pulls/[number]/_components/IntentCard/styles.ts` (`chip`).
- 2026-09-20 · Do NOT use `React.useEffectEvent` here. It type-checks and passes vitest (`node_modules/react` is 19.2.7) but CRASHES in the browser with `useEffectEvent is not a function`: Next 15.5's App Router runs its own bundled React — `node -p "typeof require('next/dist/compiled/react').useEffectEvent"` → `undefined`. Use a `latest` ref (`useRef` + an effect that assigns it) for listeners that read fresh state, until Next vendors React ≥ 19.2. Pair with "adjust state during render" (`if (prev !== x) { setPrev(x); reset(); }`) for prop-keyed resets, rather than a `useEffect` that paints one stale frame. `client/src/app/repos/[repoId]/pulls/[number]/_components/FindingsPanel/useFindingKeyboardNav.ts`, guarded by the keyboard tests in `FindingsPanel.test.tsx`. → now a rule in client/AGENTS.md.
- 2026-09-27 · `MermaidDiagram` (`client/src/components/mermaid-diagram/MermaidDiagram.tsx`) had zero consumers before `BlastGraph` — its first real usage. When node labels come from untrusted repo content (symbol/file/endpoint names), style nodes by CLASS on the synthetic id (`class n3 ddEndpoint` + a static `classDef ddEndpoint stroke:…`), never by matching on the escaped label text — the label only needs `escapeMermaidLabel` (strip `<>[]{}()|`, `"` → `#quot;`) to stay inside its own `["…"]` node declaration; a separate `class`/`classDef` pair keeps coloring independent of whatever the label contains. `client/src/app/repos/[repoId]/pulls/[number]/_components/BlastRadiusCard/helpers.ts:96` (`buildBlastMermaid`).
- 2026-09-27 · A next-intl message can read as plain fixed-plural text (`"stat.symbols": "symbols"`) with its call site passing NO params at all (`t("stat.symbols")`, count concatenated separately in JSX) — rewriting the message to an ICU `{count, plural, one {...} other {...}}` form is not enough; the call site must also start passing `{ count: n }` or the plural selector has nothing to select on and next-intl throws/renders wrong. Fixing `blast.json`'s `stat.*`/`callerCount`/`priorPrs.overlap` required checking each of the three call sites (`BlastSummary.tsx`, `SymbolRow.tsx`, `PriorPrs.tsx`) individually — two already passed `count` (no call-site change needed), one (`BlastSummary.tsx`) didn't and needed `t("stat.symbols", { count: totals.symbols })` added at all four call sites. `client/src/app/repos/[repoId]/pulls/[number]/_components/BlastRadiusCard/_components/BlastSummary/BlastSummary.tsx:21`.
- 2026-09-27 · `@testing-library/user-event` is not a client dependency (checked `client/package.json` before reaching for it) — component tests that simulate multiple clicks (e.g. paging through a "Show N more" button) use `fireEvent` instead. Don't add the dependency for a single test file; it would touch `pnpm-lock.yaml` for no plan-scoped reason. `client/src/app/repos/[repoId]/pulls/[number]/_components/BlastRadiusCard/BlastRadiusCard.test.tsx`.

## Recurring Errors & Fixes

- 2026-09-27 · A new global CSS class added mid-session to `globals.css` (e.g. `.overview-grid` for the Blast Radius two-column layout, `docs/plans/0011-blast-radius.md` Step 10) can render as if the rule doesn't exist at all — `document.styleSheets` shows the compiled `layout.css` still missing the new selector — even after killing and restarting the `next dev` process. Root cause: Next's `.next/cache` (256MB in this repo) persists across a plain process restart and can keep serving a stale compiled CSS bundle. A process restart alone is not enough; `rm -rf .next` before restarting `pnpm dev` forces a genuinely clean recompile. Confirmed live: real page load stayed single-column at 1468px `innerWidth` (`matchMedia('(min-width:900px)').matches === true`, so the media query itself was fine) until `.next` was deleted, after which the two-column grid rendered correctly. Don't diagnose a "layout looks stacked despite the CSS looking right" symptom as a logic bug in the new CSS before ruling this out.

- 2026-09-19 · `Module not found: Can't resolve './contracts/findings.js'` (page 500s under `next dev` while `tsc` and vitest pass) → keep client imports from `@devdigest/shared` as `import type`; derive runtime lists from a local `Record<Union, …>` (the compiler keeps it complete). Root cause: a RUNTIME import (e.g. `SkillType.options`) pulls in the vendored index, whose `.js` specifiers Next's webpack can't resolve; every other client file imports types only, so only a real page load catches it. `client/src/app/skills/_components/SkillsView/_components/SkillForm/constants.ts:1`. → now a rule in client/AGENTS.md.
