## Codebase Patterns

- 2026-09-17 · Run-usage UI: null and 0 mean different things for BOTH cost and tokens. Unknown cost renders "—" (`client/src/lib/format-usd.ts`, `formatUsd`); unknown tokens must DROP the whole "N tok · " segment. Never `?? 0` into `RunCostBadge` — `(r.tokens_in ?? 0) + (r.tokens_out ?? 0)` made a run with known cost but unrecorded tokens claim "0 tok". Guarded by "does not claim '0 tok'" in `RunHistory.test.tsx`. → now a rule in client/AGENTS.md.
- 2026-09-17 · Reuse `client/src/vendor/ui`'s **tokens** before its components: `SEV[x].c` / `SEV[x].icon` (`client/src/vendor/ui/primitives/tokens.ts:6`) give the right colour and glyph for any severity UI, while the matching components bake in chrome. `SeverityBadge` (`client/src/vendor/ui/primitives/Badge.tsx:52`) unconditionally draws a filled pill (`background: SEV[x].bg` + padding + radius + uppercase) with no variant prop — the timeline chips needed a bare icon+number, so the chip had to be local.
- 2026-09-17 · `FindingsTab`'s two run props are different types and trivially swapped: `runs` is `ReviewRecord[]` (each WITH `findings` and a `run_id`), `prRuns` is `RunSummary[]` (the timeline). Anything per-severity must read `runs` and join by `run_id` — `RunSummary` carries only `findings_count`/`blockers`, never a severity breakdown (`client/src/vendor/shared/contracts/trace.ts:99-121`). `client/src/app/repos/[repoId]/pulls/[number]/_components/FindingsTab/FindingsTab.tsx:17-18`.
- 2026-09-17 · The seeded review has `run_id = NULL` (`server/src/db/seed.ts:136-148` never sets it) and every real `agent_runs` row in the shared dev DB has 0 findings — so anything joining reviews to timeline runs by `run_id` renders its fallback and looks broken on seeded data. To see the timeline severity chips, temporarily `UPDATE findings SET review_id=<a review that HAS a run_id>` and put it back; don't "fix" the seed (`e2e/INSIGHTS.md` explains why).
- 2026-09-18 · When a count and the list it describes can diverge, derive them in the SAME component. The run card's severity pills must equal the finding cards below, but `FindingsPanel` owns the "hide low confidence" toggle — counting `review.findings` up in `ReviewRunAccordion` would promise cards the toggle had hidden. Counting inside the panel, post-confidence and pre-severity, makes the equality structural. `client/src/app/repos/[repoId]/pulls/[number]/_components/FindingsPanel/FindingsPanel.tsx:33`.
- 2026-09-18 · `@devdigest/ui` exports its own `Severity` with a fourth value (`INFO`) the contract's `Severity` lacks, so importing both in one file is a duplicate-identifier error and `Record<ContractSeverity, number>` won't satisfy a `Record<UiSeverity, number>` param. Type props from the CONTRACT and alias the UI one (`type Severity as UiSeverity`) at the `SeverityBadge` call. `client/src/vendor/ui/primitives/tokens.ts:3` vs `client/src/vendor/shared/contracts/findings.ts:11`.
- 2026-09-19 · The Trace drawer shows findings from TWO independent sources, so the numbers can legitimately disagree: the `FINDINGS` stat tile reads `stats.findings` off the run's `RunTrace` document; the `Findings` section below renders the separately-passed `findings: FindingRecord[]` (persisted rows). `FINDINGS 0` above a list of 3 is not a bug — don't "reconcile" without deciding which source is authoritative. `client/src/app/repos/[repoId]/pulls/[number]/_components/RunTraceDrawer/_components/TraceBody/TraceBody.tsx:19` (`TraceBody`).
- 2026-09-19 · PR-list columns derive from one `COLUMNS` array (`client/src/app/repos/[repoId]/pulls/constants.ts:1`): `GRID`, the header row and the cell order all come from it, and `PRRow` builds `cells: Record<ColumnKey, ReactNode>`, so a column added without its cell is a `tsc` error (TS2741). The one link the type system can't see is the header label `list.columns.<key>` in `prReview.json` — guarded by `client/src/app/repos/[repoId]/pulls/constants.test.ts`. (Replaces the old three-unlinked-places trap: `GRID` + `COLUMN_KEYS` + JSX cells.)
- 2026-09-19 · UI state that must survive moving between `/x` and `/x/:id` (e.g. the agents rail's "sorted once per page load" order) has to live in a Next `layout.tsx`, not a component each page renders — separate pages remount it on every navigation. `client/src/app/agents/layout.tsx:1` mounts `AgentsLayout` once; pages render only the right pane, and the create-modal trigger reaches them via `AgentsShellContext`.

## Tool & Library Notes

- 2026-09-17 · There is no popover/tooltip/hovercard primitive in `client/src` (no floating-ui/radix dep) — hand-roll it. What works against the timeline's own `overflow`: `position: fixed` anchored to `e.currentTarget.getBoundingClientRect()` captured on `onMouseEnter`, clamped with `Math.min(rect.left, window.innerWidth - width)`. Keep the card a DOM child of the hovered element — `onMouseLeave` follows DOM containment, not visual position. `client/src/components/findings-preview/styles.ts:8` (`card`).
- 2026-09-17 · `ConfidenceNum` (`client/src/vendor/ui/primitives/ConfidenceNum.tsx:8`) hardcodes `title="Model confidence"` with no prop to suppress it; on a non-interactive surface such as a hover card that lone `title` makes the browser show a help cursor (user-reported; confirmed — every element computed `cursor: default` and the repo has no `cursor: help`). Need the visual without the tooltip → duplicate its ~8 lines locally (`client/src/vendor/ui` is off-limits) with a comment saying why. Corollary: name chips with `aria-label`, never `title`. Guarded in `RunHistory.test.tsx`.
- 2026-09-19 · Verifying/screenshotting the findings UI in a browser: move the pointer off the chips BEFORE clicking or scrolling elsewhere. The preview card only closes on `onMouseLeave`, so a programmatic click/`scrollIntoView` leaves it floating over the next screenshot (it also swallowed an accordion click, toggling the wrong row). Hover a far corner first, then act. `client/src/components/findings-preview/FindingsPreviewCard.tsx:1`.
- 2026-09-19 · Two `@devdigest/ui` form traps: `Button` sets no default `type`, so any `Button` inside a `<form>` (e.g. Cancel) SUBMITS it unless given `type="button"`; and `Modal` gives children no padding (`Drawer` does), so a form dropped straight in touches the edges — wrap it in a `{ padding: 24 }` div as `CreateAgentModal` does. `client/src/vendor/ui/kit/Modal.tsx:60`. → now a rule in client/AGENTS.md.
- 2026-09-19 · `@devdigest/ui`'s `Markdown` renders into a `dd-md` div with NO stylesheet anywhere, and the global reset strips heading sizes and list bullets, so every rendered markdown reads as flat paragraphs. Don't fix `.dd-md` globally (PR descriptions and findings rely on the flat look); scope document typography to the surface that needs it, as the skill preview does with `.skill-md` in `client/src/app/globals.css:1`.
- 2026-09-20 · Do NOT use `React.useEffectEvent` here. It type-checks and passes vitest (`node_modules/react` is 19.2.7) but CRASHES in the browser with `useEffectEvent is not a function`: Next 15.5's App Router runs its own bundled React — `node -p "typeof require('next/dist/compiled/react').useEffectEvent"` → `undefined`. Use a `latest` ref (`useRef` + an effect that assigns it) for listeners that read fresh state, until Next vendors React ≥ 19.2. Pair with "adjust state during render" (`if (prev !== x) { setPrev(x); reset(); }`) for prop-keyed resets, rather than a `useEffect` that paints one stale frame. `client/src/app/repos/[repoId]/pulls/[number]/_components/FindingsPanel/useFindingKeyboardNav.ts`, guarded by the keyboard tests in `FindingsPanel.test.tsx`. → now a rule in client/AGENTS.md.

## Recurring Errors & Fixes

- 2026-09-19 · `Module not found: Can't resolve './contracts/findings.js'` (page 500s under `next dev` while `tsc` and vitest pass) → keep client imports from `@devdigest/shared` as `import type`; derive runtime lists from a local `Record<Union, …>` (the compiler keeps it complete). Root cause: a RUNTIME import (e.g. `SkillType.options`) pulls in the vendored index, whose `.js` specifiers Next's webpack can't resolve; every other client file imports types only, so only a real page load catches it. `client/src/app/skills/_components/SkillsView/_components/SkillForm/constants.ts:1`. → now a rule in client/AGENTS.md.
