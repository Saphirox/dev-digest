# Run Cost — серверна частина

**Модуль:** `@devdigest/api` · **Статус:** реалізовано ·
міграції `0010_clumsy_aqueduct.sql`, `0011_petite_molecule_man.sql`

Серверний зріз фічі Run Cost. Повна, наскрізна специфікація (включно з UI) —
[../../docs/specs/run-cost.md](../../docs/specs/run-cost.md); тут лише те, що
належить серверу.

## 1. Де саме був обрив

Вартість рахувалася й поверталася `reviewer-core`, але не зберігалася:

| Крок | Було | Де |
|---|---|---|
| `ReviewOutcome.costUsd` приходить із движка | ✅ | `reviewer-core/src/review/run.ts` |
| Сервер читає `outcome.costUsd` | ❌ **обрив** | `src/modules/reviews/run-executor.ts` — деструктуризував `{ tokensIn, tokensOut, grounding }`, `costUsd` мовчки відкидався |
| Колонка `agent_runs.cost_usd` | ❌ видалена | `src/db/migrations/0009_complex_runaways.sql` |

Тобто робота — не «порахувати ціну», а «не загубити вже пораховане».

## 2. Що зберігаємо

У БД лежить **готове USD, пораховане один раз на момент запуску**, а не токени
для множення на прайс під час читання. Ціни моделей змінюються (`PriceBook`
оновлюється кожні 6 год) — якби вартість рахувалася на читанні, історичні
запуски заднім числом дорожчали б і дешевшали. Токени зберігаються окремо
(`tokens_in`/`tokens_out`) і для вартості не використовуються.

`cost_usd` — `double precision NULL`. **`NULL` означає «невідомо», а не нуль.**
Бекфілу немає: історичні рядки після `0009` лишаються `NULL`, бо порахувати їх
із токенів × прайс дало б цифри, що не зійдуться з дашбордом провайдера.

## 3. Агрегація на читанні

`src/modules/pulls/routes.ts`, ендпоінт `GET /repos/:id/pulls`.

Колонка COST у списку PR — **сума всіх успішних (`status='done'`) прогонів** по
PR. Прогін, що ще виконується, вартості не має; невдалий — не матиме ніколи.

Правила `NULL` (перевірені в `test/pulls-cost-total.it.test.ts`):

| Ситуація | Результат |
|---|---|
| немає завершених прогонів | `null` → UI малює `—` |
| є завершені, але в усіх `cost_usd IS NULL` | `null` → `—` |
| частина прогонів має вартість | сума наявних; `null`-прогони просто пропускаються |

Жодна з цих гілок не перетворює «невідомо» на `0`.

> Історична примітка: перша редакція показувала вартість **останнього**
> прогону. Змінено на суму — див. рішення D1 у наскрізній специфікації.

## 4. Індекс

`agent_runs` не мав жодного індексу, хоча обидва гарячі читання сортують по
`(pr_id, ran_at desc)`: `listRunsForPull` і агрегація вартості вище. Додано
`agent_runs_pr_ran_at_idx` (`src/db/schema/runs.ts`, міграція `0011`).

## 5. Контракти

`cost_usd` протягнутий через `RunSummary` і `PrMeta`
(`src/vendor/shared/contracts/{trace,platform}.ts`). Обидва поля `nullish` —
`PrMeta` водночас описує форму GitHub-адаптера `listPullRequests`, який про
вартість нічого не знає.

**Копій контрактів дві**: канонічна тут і ручна в `client/src/vendor/shared`.
Скрипта синхронізації немає — зміну треба свідомо внести в обидві.

## 6. Поза скоупом

- Бюджети, ліміти, алерти на перевитрату.
- Вартість на екранах Agent Performance / Eval Dashboard / CI Runs
  (`eval_runs.cost_usd` і `ci_runs.cost_usd` у схемі є, але це заготовки під
  майбутні уроки).
