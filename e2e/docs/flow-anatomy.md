# Анатомія e2e-потоку

Довідка по `@devdigest/e2e`: як влаштований потік і чому саме так. Запуск і
таблиця покриття — у [../README.md](../README.md).

## Потік — це JSON зі списком команд

```jsonc
{
  "name": "App boots and lands on a repo's PR list",
  "description": "…",
  "steps": [
    { "cmd": ["open", "{BASE}/"],         "label": "load the app root" },
    { "cmd": ["wait", "--url", "/pulls"], "label": "root redirects to PRs" }
  ]
}
```

`agent-browser` — це CLI, а не тест-фреймворк. `run.ts` просто програє список
команд в одній спільній сесії браузера.

- `{BASE}` → `E2E_BASE_URL` (типово `http://localhost:3000`).
- **Ненульовий код виходу будь-якої команди валить крок і весь потік.** Тому
  `wait --text` / `wait --url` **і є** перевірками — окремого кроку-асерту для
  звичайного випадку не існує.
- Необов'язковий `"assert": { "stdoutIncludes": "…" }` додає перевірку підрядка
  в stdout команди.

## Локатори лише детерміновані

`--url`, `--text`, `find role|text|label`. Команду `chat` (AI-пошук елемента)
**не використовуємо ніколи** — прогони мають бути стабільними й без ключів.

## Чого раннер не вміє

**Наведення.** Серед дієслів немає `hover`. Фічу, що живе лише на наведенні
(картка прев'ю знахідок), покрити тут неможливо — вона лишається за vitest.

Це не формальність: потік, який «перевіряє» таке через `wait --text`, проходить
і з вирізаною фічею, тобто не перевіряє нічого. Краще не писати його зовсім.

## Дані — лише насіннєві й лише на читання

Потоки працюють із демо-репозиторієм `acme/payments-api`, PR #482 і
насіннєвими агентами. **Жоден потік не викликає модель.**

Два обмеження насіння, через які легко написати марний потік:

1. PR #482 має рівно одну `CRITICAL` і одну `WARNING` знахідку — і **жодної**
   `SUGGESTION`;
2. насіннєве рев'ю має `run_id = NULL`, тож воно не з'єднується з жодним
   прогоном таймлайна.

Через (2) все, що будується на зв'язці «прогін → його знахідки», на насінні
показує порожньо. Не «лагодь» це редагуванням `seed.ts` — потік `04` перевіряє
насіннєву кількість («2 findings») і зламається. Міняй локальну БД і повертай
назад.

## Чому тут немає продуктових специфікацій

`specs/` у цьому пакеті — це **потоки**, а не специфікації фіч. Щоб не плодити
плутанину з однаковою назвою теки, продуктових специфікацій сюди не клали;
вони живуть у `docs/specs/` кореня та в `specs/` відповідних пакетів.

## Де дивитися при падінні

Скриншоти невдалих кроків — `e2e/test-results/` (у git не потрапляють,
вивантажуються як артефакт `e2e-web.yml`).
