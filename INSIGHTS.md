## What Works

- 2026-09-20 · Any feature whose logic is a KEYWORD/HEURISTIC MATCHER needs a direct probe on realistic input before it is called done — reading it, reviewing it and type-checking it all miss the same class of bug, and the read-only review agents explicitly decline it (`architecture-reviewer` judges boundaries, not matching quality; it wrote "judging that is correctness review, not a boundary question" and moved on). Two for two this session: the Intent Layer's scope filter matched any shared >=3-char token, so the real phrase "Logging / observability **for** the limiter" dropped two unrelated WARNINGs via the word `for`; the Risk Areas `new_dependency` detector applied a `"key": "value"` regex to every added `package.json` line, so an npm script echoed `DEPLOY_TOKEN=ghp_...` into the API response and invented two "New dependency" rows. Both were found in minutes by importing the real module in a scratch `tsx` script and feeding it the wording from the actual product screenshot / a plausible manifest — neither was caught by the unit tests, which used distinctive words ("authentication") and well-formed fixtures. Method: probe with the input a USER would produce, not the input a test author invents. Then keep the probe as the regression test (`server/test/reviews-scope-filter.test.ts` "filler word", `server/test/risks-detectors.test.ts` sentinel cases). See also the command-gate entry under *Tool & Library Notes* — same lesson one layer down.

- 2026-09-20 · A `/pr-self-review` reviewer subagent that appends to any `INSIGHTS.md` mid-run INVALIDATES the whole run: the verdict is keyed to one exact diff, so the append makes `verdict.mjs` return STALE and every unit has to be re-planned. Seen with `reviewer-core/INSIGHTS.md` written 5 minutes after `prepare.mjs` by the typescript-expert unit. Two consequences: (1) tell every reviewer explicitly NOT to write insights and to hand candidates back in its reply instead — several did so correctly once told, citing the clobber risk of parallel writes to one file; (2) make the insights append the LAST action of a task, after the final verdict. The same rule covers any agent writing to a tracked file during a review — a doc-writer run in parallel has to be scoped to files the reviewers are not reading.
- 2026-09-20 · To check a prompt-vs-mechanism question (does a hook or `tools:` limit really block a subagent?), give the subagent a real task plus one instrumented step, tell it a block is the SUCCESS condition and must not be retried or worked around, and have it quote the deny text verbatim — one run settled per-subagent hook enforcement. `.claude/agents/investigator.md`

- 2026-09-21 · Supersedes the regression-test pointer in the 2026-09-20 "keyword matcher needs a direct probe" entry: `server/test/reviews-scope-filter.test.ts` no longer exists — the matcher itself was removed (plan 0008), because probing it with a live model's real wording showed it could not be fixed by better keywords, only by moving the judgement to the component that has seen the code. The lesson stands; the successor guards are `reviewer-core/test/prompt.test.ts` and the off-topic case in `server/test/reviews-intent.it.test.ts`. Corollary: when two rounds of probe-and-patch on a heuristic each find a new real defect, stop patching and ask whether the heuristic should exist at all.
